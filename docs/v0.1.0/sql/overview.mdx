# SQL overview

**Source of truth:** the implementation — parser, AST, and executor. Only behavior verified there is documented below.

## Statements

| Statement | Status | Page |
| --- | --- | --- |
| `SELECT` | Supported | [SELECT](/v0.1.0/sql/select) |
| `INSERT` (values / default / select / conflict / returning) | Supported | [INSERT](/v0.1.0/sql/insert) |
| `UPDATE` (+`FROM`, JSON targets, `RETURNING`) | Supported (Partial: `UPDATE…FROM` not in explicit txn) | [UPDATE](/v0.1.0/sql/update) |
| `DELETE` (+`USING`, `RETURNING`), `TRUNCATE` | Supported | [DELETE](/v0.1.0/sql/delete) |
| `CREATE TABLE \| DATABASE \| SCHEMA \| VIEW \| INDEX \| SEQUENCE \| TYPE \| DOMAIN` | Supported | [DDL](/v0.1.0/sql/ddl) |
| `CREATE MATERIALIZED VIEW \| FUNCTION \| PROCEDURE \| TRIGGER \| EXTENSION`, `CREATE ROLE/USER` | Parse to stubs or limited forms without full execution (`DROP ROLE/USER` supported with guards — see roles page) | [DDL](/v0.1.0/sql/ddl) |
| `ALTER TABLE` (rename/add/drop), `DROP …`, `COMMENT ON` | Supported subset | [DDL](/v0.1.0/sql/ddl) |
| \`BEGIN | START TRANSACTION | COMMIT | ROLLBACK | SET TRANSACTION\` | Supported | [Transactions](/v0.1.0/transactions/using-transactions) |
| `SET`, `SHOW`, `DESCRIBE`, `USE`, `GRANT`/`REVOKE` (roles and object privileges, including `ALL TABLES IN SCHEMA`) | Supported | [DDL](/v0.1.0/sql/ddl), [Roles](/v0.1.0/sql/roles-permissions) |
| `WITH [RECURSIVE]`, `EXPLAIN [ANALYZE]` | Supported | [Subqueries + CTEs](/v0.1.0/sql/subqueries-cte), [EXPLAIN](/v0.1.0/sql/explain) |
| \`COPY … FROM STDIN | TO STDOUT\` (wire only) | Supported; file COPY rejected | [DDL](/v0.1.0/sql/ddl) |
| `VACUUM` | Accounted maintenance trigger (64-mutation policy, fails closed) | [DDL](/v0.1.0/sql/ddl) |
| `ANALYZE` | Real statistics collection (executed over the wire; counted in `plomid_stat_admin()`) | [DDL](/v0.1.0/sql/ddl) |
| `REINDEX` | Drops cached ANN graphs, revalidates vector index metadata (recorded in `plomid_stat_admin()`) | [DDL](/v0.1.0/sql/ddl) |
| `LOCK \| CLUSTER \| REFRESH \| DO \| PERFORM \| RAISE \| LISTEN \| NOTIFY` | Acknowledged over client connections, no engine effect | [Compatibility](/v0.1.0/sql/compatibility) |
| `DEALLOCATE \| DISCARD \| RESET \| TABLE \| PREPARE` as SQL | Not supported (syntax errors) | [Compatibility](/v0.1.0/sql/compatibility) |

`CREATE MATERIALIZED VIEW`, `CREATE TRIGGER/PROCEDURE/EXTENSION` parse to stubs without execution. `REFRESH MATERIALIZED VIEW` is acknowledged without effect.

## Clauses and features

Expressions, operators, functions, aggregates, joins, subqueries, ordering/grouping, pagination, aliases, casts, NULL, JSON, temporal: each has a dedicated page linked from [SELECT](/v0.1.0/sql/select).

## Compatibility philosophy

Similar syntax ≠ compatibility. PLOMID speaks the PG wire protocol and mirrors PG type OIDs, but the executor is its own. [Compatibility](/v0.1.0/sql/compatibility) lists implemented / partial / unsupported / different-behavior explicitly. No `PostgreSQL-compatible` claim is made beyond the wire + catalog surface that is actually implemented.
