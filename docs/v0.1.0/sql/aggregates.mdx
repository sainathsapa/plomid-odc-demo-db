# Aggregations

Supported aggregates: `COUNT SUM AVG MIN MAX STRING_AGG ARRAY_AGG JSON_AGG JSONB_AGG JSON_OBJECT_AGG JSONB_OBJECT_AGG JSON_ARRAYAGG JSON_OBJECTAGG`.

```sql
SELECT count(*), count(email), count(DISTINCT city) FROM users;
SELECT sum(total), avg(total), min(total), max(total) FROM orders;
SELECT string_agg(name, ', ' ORDER BY name), array_agg(id ORDER BY id) FROM users;
SELECT json_agg(payload), jsonb_agg(payload), json_object_agg(name, id) FROM users;
SELECT user_id, count(*) FROM orders GROUP BY user_id HAVING count(*) > 1;
SELECT a, b, count(*) FROM t GROUP BY GROUPING SETS ((a,b),(a),());
SELECT count(*) FILTER (WHERE total > 100) FROM orders;
```

## Behavior

- `COUNT(*)` counts rows; `COUNT(expr)` skips NULL; `COUNT(DISTINCT)` dedups by `to_sql_text` (unifies `1`/`1.0`).
- `SUM` typing (PostgreSQL): `SUM(int2/int4)` → `bigint`, `SUM(int8)`/`SUM(numeric)` → `numeric` (exact, OID 1700), `SUM(float4/float8)` → `float8` (OID 701). Empty/all-NULL → NULL.
- `AVG` typing (PostgreSQL): `AVG(int2/int4/int8/numeric)` → `numeric` (normalized, e.g. `21` not `21.0000`), `AVG(float4/float8)` → `float8`. Empty/all-NULL → NULL.
- Mixed-type feeds (e.g. `NUMERIC` column with integer/float expression rows, window frames mixing types) consume every non-NULL value: integers convert exactly via `from_i64`, floats via `from_f64`. The first non-integer decides the representation (numeric stays exact, float stays `f64`); mixed float+`NUMERIC` is first-wins and order-dependent by design (columns are uniform in practice, so this only affects expressions).
- `Numeric::div` scale is `max+4` truncation (e.g. `AVG` of `800/3` is `266.6666`, not PG `266.6666666666666667`); `from_f64` maps non-finite to `0`.
- `MIN/MAX` via `value_cmp`, NULL skipped, empty → NULL.
- `JSON_AGG` keeps per-row values incl. SQL NULL→JSON null; `JSON_OBJECT_AGG` skips NULL keys.
- Modifiers: `DISTINCT` (fully distinct-aware for `COUNT`; `SUM(DISTINCT)`/`AVG(DISTINCT)` consistent via the join engine), `FILTER (WHERE …)`, `agg(x ORDER BY … [NULLS FIRST|LAST])` (ordering inside `STRING_AGG`/`ARRAY_AGG` honored; `AVG(x ORDER BY y)`/`SUM(x ORDER BY y)` parse but ignore ordering — scan order is used).
- Bare `SELECT COUNT(*) ` without `WHERE` answered by key count.

**General engine trigger:** `string_agg/array_agg/json_*agg`, non-column GROUP BY, multi-sets, or GROUP BY+ORDER BY.
