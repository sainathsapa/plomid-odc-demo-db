# SHOW and DESCRIBE

```sql
SHOW tables;  SHOW table;  SHOW schemas;  SHOW schema;  SHOW schema_name;
SHOW databases;  SHOW database;  SHOW search_path;
SHOW server_version;  SHOW timezone;  SHOW transaction_isolation;
DESCRIBE users;  DESC orders;
```

## Inventory queries

| Statement | Output column | Rows |
| --- | --- | --- |
| `SHOW tables` / `SHOW table` | `table_name` | bare table names in search scope |
| `SHOW schemas` / `SHOW schema` | `schema` | sorted, deduped (tables imply their schema, default `public`) |
| `SHOW schema_name` | `schema_name` | single row: `public` |
| `SHOW databases` / `SHOW database` | `database` | registered database names |
| `SHOW search_path` | `search_path` | e.g. `"$user", public` (`$user` quoted) |

## Fixed parameters

| Parameter | Returns |
| --- | --- |
| `transaction_read_only` | `off` |
| `transaction_isolation` | `read committed` |
| `standard_conforming_strings` | `on` |
| `integer_datetimes` | `on` |
| `timezone` | `UTC` |
| `server_version` | `14.0` |
| `application_name` | `plomid` |
| `extra_float_digits` | `3` |
| `vector.<knob>` | current value of any of the 9 vector settings (`ann_enabled`, `ef_search`, `candidate_oversample`, `max_ann_rows`, `cache_graphs`, `max_index_vectors`, `auto_ann_min_rows`, `compute`, `max_memory_bytes`) — see [Vector indexes](/v0.1.0/vector/indexes) |

`SET` accepts `search_path`, any `vector.*` knob, and the standard session keys below; any _other_ `SET name` is stored in-session and acknowledged with `SET` without dispatching to the engine (so driver-sent keys like `extra_float_digits`, `application_name`, or `lock_timeout` never error — but only the keys above change behavior). `SET ROLE` / `SET SESSION AUTHORIZATION` are accepted the same way without changing the authenticated role. `RESET`, `RESET ALL`, and `DISCARD ALL` are **not supported** (syntax error) — poolers that send them on checkout need those statements disabled.

<Note>
  **Two true versions:** the wire-protocol startup parameter reports `server_version 17.0` (`server_version_num 170000`), while `SHOW server_version` and `pg_settings` report `14.0` (`140000`). Tools reading the startup packet see 17.0; SQL-level introspection sees 14.0. Both are current v0.1.0 behavior — match on prefix, not equality, if you gate features by version.
</Note>

## DESCRIBE output

```sql
DESCRIBE orders;
-- columns: column_name | data_type | ordinal_position | is_nullable
-- is_nullable: YES | NO (from NOT NULL constraints)
```

`DESC` is an alias. Unknown table → storage error.
